# Product Requirements Document(PRD)

## 1. 프로젝트 개요(Project Overview)

- **프로젝트 명** : AI Dream Teller(AI 꿈 해몽 서비스)

- **목표** : 사용자가 입력한 꿈 내용을 AI가 분석하여 심층적인 해몽과 조언을 제공하는 수익형 웹 서비스

- **핵심 가치 1** : 신비롭고 직관적인 UI경험과 정확도 높은 AI 분석을 통해서 사용자에게 인사이트와 재미를 제공
- **핵심 가치 2** : 프로이트, 칼 융, 신경과학, 게슈탈트 등 해몽을 맡기고 싶은 전문 분야를 선택해서 해몽 요청을 가능하게 함.

## 2. 타겟 유저(Target Audience)

- 꿈의 의미를 검색해보는 습관이 있는 20~40대 남녀.
- 모바일 환경에서 간편ㅇ하게 결과를 확인하고 공유하고 싶어하는 유저.

## 3. 기술 스택(Tech Stack)

- **Web Framework** : Next.js (App Router)
- **Language** : TypeScript
- **Styling** : Tailwind CSS, Shadcn/UI
- **Backend & DB** : Next.js API Routes, Supabase
- **Payment** : Toss Payments
- **AI Services** : Gemini with gemini sdk

## 4. 디자인 가이드(Design Guide)

- **Theme** : Soft, Ethereal, Fluid (밝고 부드러운 테마)
- **Colors** : Ivory, Pastel Purple, Soft Blue, Warm Pink (은은한 파스텔 톤 및 아이보리 배경)
- **Interactions** : 부드러운 스크롤, 호버 시 은은한 그림자 및 빛 효과, 로딩 시 몽환적인 애니메이션
- **Typography** : 적절한 폰트사이즈와 줄바꿈으로 가독성 확보

## 5. UX Flow & Layout

### 5.1. 전체 레이아웃 (Overall Layout)

1. **상단 네비게이션 바**
   - (공통) 홈 로고 (클릭 시 메인 페이지 이동). 서비스 정체성을 살리기 위해 세리프(Serif), 이탤릭체, 그라데이션 텍스트를 적용하여 몽환적이고 신비로운 분위기 연출
   - (비회원) 로그인 (현재 초기 단계이므로 비회원 주문 조회 제외, 로그인 버튼만 테마 컬러에 맞춘 둥근 버튼 UI로 강조)
   - (회원) 마이페이지 (로그인 연동 후 동적 노출 예정)
   - **(모바일 반응형)** 화면이 작아질 경우 텍스트 메뉴가 숨겨지고 우측에 햄버거 메뉴 버튼 노출. 버튼 클릭 시 상단에서 아래로 펼쳐지는 Drawer(Sheet) 메뉴 제공. 하단을 둥글게(Rounded) 처리하고 배경에 블러(Backdrop blur) 효과를 주어 프리미엄 앱 같은 UI 제공
2. **Body**
   - 각 페이지 별 주요 내용 렌더링 (꿈 입력, 분석 결과, 마이페이지 등)
3. **Footer**
   - 하단 카피라이트 텍스트 및 사업자 정보 텍스트 직접 표기 (상호, 대표자, 사업자등록번호, 이메일 등)
   - 우측(또는 하단) 링크 영역: 이용약관(`/terms`), 개인정보처리방침(`/privacy`), 문의하기(이메일 링크) 제공
4. **Head & Meta**
   - SEO 최적화 (Title, Description)
   - Open Graph (SNS 공유 시 노출 정보)
   - GA4 등 Analytics 설정 및 데이터 트래킹

### 5.2. 페이지 별 UX 구성 (UX Flow & Pages)

1. **메인 랜딩페이지 (`/`)**

   #### Hero 섹션
   - **한 줄 문구 (헤드라인)**: `"오늘 밤 꿈, 아직도 기억나세요?"`
     - 유저가 방문하는 순간(꿈을 꾼 직후)의 상황에 즉각 공감. 추상적인 슬로건 대신 구체적인 상황 묘사로 이탈율 감소
   - **상세 소개 (서브 카피)**: `"프로이트의 정신분석, 칼 융의 원형 이론, 최신 신경과학 연구를 학습한 AI가 꿈 속 상징과 감정을 분석합니다. 단 3분, 내 무의식이 건네는 특별한 메시지를 확인해 보세요."`
     - 과학적 권위(프로이트·융·신경과학) 강조로 미신 느낌 완전 배제
     - "단 3분" 반복 노출로 낮은 시간 비용 인식 유도 및 부드러운 감성 표현으로 유도
   - **CTA 버튼**: `"지금 내 꿈 해석받기 →"` (프로덕트 상세 페이지 `/dream-teller`로 이동)
     - "내"라는 1인칭 소유격으로 개인화 효과 + 수동형("받기")으로 낮은 심리적 마찰

   #### Feature 소개 섹션 (Bento Grid)
   - **섹션 타이틀**: `"꿈 해몽, 이제 이렇게 달라집니다"`
   - **카드 1 (대형 강조 카드)**: 제목 `"3가지 시각으로 읽는 당신의 꿈"` / 설명: 프로이트 정신분석·칼 융의 원형 이론·현대 신경과학 데이터를 통합하여 꿈 속 상징과 감정이 내포한 의미를 다층적으로 풀어냄
   - **카드 2 (속도/편의)**: 제목 `"입력하고 3분이면 끝"` / 설명: 꿈 내용을 자유롭게 적으면 AI가 상징·감정·패턴을 즉시 분석. 복잡한 절차 없음
   - **카드 3 (이미지/업셀 유도)**: 제목 `"꿈속 장면, 눈으로 확인하세요"` / 설명: 텍스트 해석에 AI 생성 이미지를 추가하면 꿈의 감성을 시각적으로 간직 가능 (+ 500원 옵션)
   - **카드 4 (리텐션 유도)**: 제목 `"꿈 기록이 곧 나의 심리 일기"` / 설명: 해석된 꿈들이 자동 저장되어 시간이 지날수록 내 무의식의 패턴을 발견 가능

   #### 소셜 프루프 섹션 (피드 예시)
   - 이미 풀이된 이전 유저들의 꿈 해몽 텍스트 및 AI 이미지 예시 리스트 (더보기 클릭 시 예시 리스트 피드(`/feeds`)로 이동, 각 예시 카드 클릭 시 해당 꿈 해몽 결과 상세 페이지(`/dream-result/[id]`)로 이동)
   - 다른 유저들의 실제 해석 결과를 보여줌으로써 신뢰도 및 구매 전환율 제고

2. **프로덕트 상세 페이지 (`/dream-teller`)**
   - 간략한 서비스 사용 소개
   - 입력 플로우는 전체적으로 아코디언(Accordion) 메뉴 방식으로 제공되며, 각 단계를 완료하면 자동으로 다음 단계로 화면이 스크롤되도록 UX를 구성함.
   - **Step 1.** 프로이트, 칼 융, 신경과학, 게슈탈트 등 해몽을 맡기고 싶은 전문 분야 선택
   - **Step 2.** 유저의 꿈 입력란 (입력 창 하단에 명시적인 '다음 단계로 넘어가기' 버튼 제공)
   - **Step 3.** 결제 옵션 선택
     - (기본) 단순 텍스트 해석 : 1,500원
     - (추가 옵션) AI 생성 이미지 추가 : +500원 (디폴트로 체크된 상태로 제공)
   - 안내 및 주의 사항
     - 보통 3분 이내에 생성이 완료됩니다.
     - 꿈 해석은 AI를 통해 정신분석, 신화, 상징학 데이터를 기반으로 생성됩니다.
     - 이 해석은 자기 이해를 돕기 위한 참고 자료이며, 의학적/심리학적 진단을 대체하지 않습니다.
   - 꿈 풀이 요청 버튼 (하단 고정형 CTA)

3. **결제 페이지 (`/payments`)**
   - 영수증 디자인을 참고한 디자인의 결제 페이지
   - 토스페이먼츠 위젯이 들어갈 섹션
   - 회원 결제와 비회원 결제 모두 지원
   - 결제가 성공적으로 완료된 후 회원은 마이페이지, 비회원은 비회원 주문 조회 페이지로 이동
   - 결제에 실패했을 경우 입력한 꿈 정보가 사라지지 않고 결제 페이지에 그대로 머물러 있음

4. **해석 확인 페이지 (`/dream-result/[order-id]`)**
   - 결제한 유저가 자신의 꿈 해석 및 AI 이미지(옵션)를 확인할 수 있는 페이지 (현재 더미 데이터 적용 완료)
   - 해몽과 이미지 뿐 아니라 자신이 입력한 꿈 내용도 함께 확인할 수 있어야 함 (완료)
   - 다른 사람에게 공유할 수 있도록 링크 카피, 소셜 공유 버튼 섹션 하단 배치
     - **(구현 완료)** 링크 복사(`navigator.clipboard`) 및 **카카오톡 공유하기(Kakao JS SDK 연동)** 기능 반영
   - **(회원의 경우)** 캘린더 라이브러리를 활용해 해몽이 이뤄진 날짜에 하이라이트 표시 및 해당 일자를 누를 경우 해당 해몽 결과 페이지로 넘어감
     - **(구현 완료)** `shadcn/ui`의 Calendar 컴포넌트를 사용하여 회원인 경우(`isOwner=true`)에만 달력 렌더링. 서버와 클라이언트 간의 Hydration Mismatch(로케일, Date 객체 차이) 에러를 방지하기 위해 Mounted 패턴 적용.
   - **(공개/비공개 토글)** 해몽 결과의 소유자인 경우, 자신의 해몽을 피드에 공개하거나 나만 볼 수 있도록 비공개 처리할 수 있는 토글 스위치 제공. 몽환적인 테마(Soft, Ethereal)에 맞춘 디자인 적용 완료.
   - **(폰트 적용)** 몽환적이고 감성적인 분위기를 위해 본문은 `Noto Sans KR`, 제목 및 캘린더 등 주요 섹션은 명조체인 `Hahmlet` 폰트를 `next/font/google`로 전역 적용.
   - **(외부 이미지 지원)** AI 생성 이미지 노출을 위해 `next.config.ts`에 `picsum.photos` 외부 이미지 도메인 허용 설정 완료.

5. **유저의 마이페이지 (`/my-page`)** ✅ 구현 완료
   - 회원 가입된 유저만 자신의 마이페이지 접근 가능 (미인증 시 /auth 리다이렉트)
   - 캘린더 라이브러리(react-day-picker)를 활용해 해몽이 이뤄진 날짜에 하이라이트 표시 및 해당 일자를 누를 경우 해당 해몽 결과 페이지로 넘어감
   - 구매 내역 리스트가 캘린더 하단에 배치 및 해당 리스트 아이템을 누를 경우 해당 해몽 결과 확인 페이지로 넘어감
   - 닉네임(수정 가능 기능), 로그인 한 소셜 서비스(구글 or 카카오) 로고, 이메일 주소, 로그아웃 버튼
   - 헤더 네비게이션: 로그인 상태에 따라 로그인/마이페이지 버튼 동적 분기
   - TODO: Supabase 연동 후 실제 구매 내역 데이터 교체, 닉네임 수정 API 연동

6. **비회원 로그인 (`/guest-login`)**
   - 간단한 페이지 소개
   - 전화번호 및 비밀번호 입력 폼
   - 비회원 주문 조회 버튼

7. **비회원 주문 조회 페이지 (`/guest-check`)**
   - 6번에서 로그인한 비회원이 자신의 구매 내역을 조회하는 페이지
   - 구매내역 리스트가 배치되어 있고 해당 리스트 아이템을 눌렀을 때, 해당 해몽 결과 확인 페이지로 이동

8. **이전 유저들의 과거 풀이 내역 리스트 피드 페이지 (`/feeds`)**
   - 페이스북 형태의 피드
   - 이미지가 있는 해몽 결과는 이미지와 텍스트가 함께 보여지고, 텍스트만 있는 해몽 결과는 텍스트만 보여짐

9. **회원 로그인 페이지 (`/auth`)** ✅ 구현 완료
   - 구글 및 카카오 소셜 로그인만 존재 (각 공식 브랜딩 가이드라인 준수)
   - 각 소셜 서비스로 성공적으로 로그인 후 리다이렉트는 2번의 프로덕트 상세 페이지로 이동
   - 환경별 도메인 분기: `NEXT_PUBLIC_SITE_URL` 환경변수 기반 (개발: localhost / 프로덕션: 실제 도메인)
   - Supabase SSR 인증 아키텍처: `@supabase/ssr` 기반 proxy.ts 세션 갱신 + OAuth 콜백 처리

10. **이용 약관 페이지 (`/terms`)** ✅ 구현 완료
    - 서비스 이용 관련 권리, 의무, 환불 정책 등 법적 고지사항 제공

11. **개인정보처리방침 페이지 (`/privacy`)** ✅ 구현 완료
    - 개인정보 수집 항목, 목적, 보유 기간 및 데이터 익명화 관련 정책 제공

12. **문의하기 페이지 (`/contact`)** ✅ 구현 완료
    - **좌측 영역**: 서비스 이용, 환불, 회원/비회원 차이점 등을 안내하는 **자주 묻는 질문(FAQ)** 아코디언 메뉴와 영업일 기준 1~2일 내에 답변된다는 내용이 포함된 직접 문의 이메일 박스 노출
    - **우측 영역**: 문의 제목, 회신 받을 이메일, 문의 내용을 입력하고 발송할 수 있는 직관적인 **문의하기 폼(Form) UI** 제공 (현재 폼 제출 시 Alert 창으로 임시 접수 처리됨)

### 5.3. 관리자 UX 페이지 구성 (Admin UX Flow & Pages)

   - **좌측 네비게이션 사이드바 (`AdminSidebar`)**: 매출 대시보드, 주문 내역 리스트, 유저 리스트 링크 제공 및 현재 페이지 활성화 하이라이트 효과 적용. 하단 사용자 홈 바로가기 및 로그아웃 버튼 탑재.
   - **상단 어드민 헤더 (`AdminHeader`)**: 어드민 계정 정보(프로필, 역할) 요약 표시 및 알림 센터 플레이스홀더 제공.
   - **본문 영역 독립 스크롤 (`main`)**: 반응형 최대 너비(max-w-7xl) 제한 및 프리미엄 오로라 장식 광원 배경 적용.

## 6. API 구조 설계 (API Architecture)

Next.js 14 App Router의 `app/api/.../route.ts` (Route Handlers) 및 Supabase 기반으로 설계된 MECE한 API 구조입니다.

### 6.1. Auth & Users (`/api/auth`, `/api/users`)

Supabase Auth와 연동하여 인증 및 확장된 유저 정보를 관리합니다.

- `POST /api/auth/guest` : 비회원용 세션 토큰 발급 (비회원 주문 조회용)
- `GET /api/auth/callback` : 소셜 로그인(Google, Kakao) 인증 후 콜백 처리 및 세션 저장
- `POST /api/auth/sign-out` : 로그아웃 처리 및 세션 파기
- `GET /api/users/me` : 현재 로그인한 유저의 프로필 정보 및 남은 크레딧/결제 상태 조회
- `PATCH /api/users/me` : 유저 프로필(닉네임 등) 수정

### 6.2. Feeds (`/api/feeds`)

메인 랜딩 등에 노출되는 공개 데이터를 처리합니다.

- `GET /api/feeds` : 메인 랜딩용 공개 해몽 결과 목록 조회 (Pagination 지원)

### 6.3. AI Processing (`/api/ai`)

해몽 생성 및 이미지 비동기 처리를 담당합니다.

- `POST /api/ai/generate` : 결제 완료 건을 대상으로 Gemini API를 활용하여 해몽 분석 및 이미지 생성 작업 비동기 트리거
  - **해몽 결과 알림 (Telegram Bot)**: 꿈 해몽 생성이 완료되어 DB에 최종 입력되거나 에러가 발생하여 실패할 때, 텔레그램 봇을 통해 관리자에게 상태 알림(Success/Fail)을 전송합니다.
  - **AI 이미지 생성 파이프라인 (조건부 실행)**:
    - **결제 옵션 검증**: 주문의 결제 금액이나 옵션을 확인하여, 이미지 생성 상품이 포함된 주문건에 대해서만 이미지 생성 로직을 실행합니다.
    - **프롬프트 엔지니어링**: 텍스트 해몽 결과와 원본 꿈 내용을 바탕으로, 이미지 생성 모델에 적합한 영문 프롬프트를 자동 생성(LLM 활용)합니다.
    - **이미지 생성 및 스토리지 저장**: 외부 이미지 생성 API를 호출하여 이미지를 생성한 뒤, 결과 이미지를 Supabase Storage에 업로드하여 영구적인 URL을 확보하고 이를 DB(`dreams` 테이블 등)에 저장합니다.
    - **예외 처리 및 상태 분리**: 이미지 생성이 실패하더라도 텍스트 해몽 결과는 정상적으로 DB에 저장되어야 하며, 알림 시 이미지 생성 실패 여부를 구분하여 전송합니다.

### 6.4. Dreams (`/api/dreams`)

생성된 꿈 해몽 결과 조회 및 관리를 담당합니다.

- `GET /api/dreams/[id]` : 특정 꿈 해몽 및 이미지 상세 조회 (공유 링크 및 상세 페이지용, 권한 체크)

### 6.5. Orders & Payments (`/api/orders`, `/api/payments`)

주문서 생성, 결제 승인, 결제 실패 및 비동기 웹훅 처리를 포함한 결제 서버 로직 전반을 담당합니다. 클라이언트의 가격 조작을 방지하고 회원/비회원 결제를 모두 안전하게 처리합니다.

- `POST /api/orders` : 결제 전 주문 정보 생성 (가주문 생성)
  - **보안/검증**: 클라이언트가 전송한 결제 금액을 신뢰하지 않고, 서버에서 직접 옵션(텍스트 기본/이미지 추가 등)을 기반으로 최종 결제 금액을 계산 및 검증하여 DB에 저장합니다.
  - **비회원 연동**: 비회원의 경우 결제 전 입력한 정보(전화번호, 비밀번호 등)를 바탕으로 `guests` 테이블에 레코드를 생성하거나 식별하여 `guest_id`를 매핑합니다.
- `GET /api/orders/[id]` : 특정 주문 단건 상세 조회 (주문 상태 유효성, 결제 금액 등 확인용)
- `GET /api/orders/me` : 현재 세션(회원 토큰 또는 비회원 로그인 세션)을 기반으로 전체 주문/결제 내역 조회 (마이페이지 캘린더 및 비회원 주문 내역 조회용)
- `POST /api/payments/toss/confirm` : Toss Payments 결제 승인 요청 및 서버 상태(`SUCCESS`) 업데이트
  - **금액 교차 검증**: 결제 승인 요청 전후로 실제 DB의 주문 금액과 토스페이먼츠 측 결제 금액이 일치하는지 재검증하여 위변조를 완벽히 차단합니다.
  - **결제 성공 알림 (Telegram Bot)**: 결제가 성공적으로 완료되면 텔레그램 봇을 통해 관리자에게 알림(결제 상품, 유저 아이디, 결제 가격, 꿈 내용 앞부분, 결제 성공 상태)을 전송합니다.
- `GET /api/payments/toss/fail` : 사용자의 결제 취소, 잔액 부족 등 결제창 이탈 및 실패 시 호출되어 해당 주문 상태를 `FAILED`로 안전하게 업데이트합니다.
  - **결제 실패 알림 (Telegram Bot)**: 결제 실패 시 텔레그램 봇을 통해 관리자에게 알림(결제 상품, 유저 아이디, 결제 실패 및 실패 내용)을 전송합니다.
- `POST /api/payments/toss/webhook` : 토스페이먼츠 비동기 상태 변경(가상계좌 입금 확인, 결제 취소 등)에 대응하기 위한 웹훅 수신 엔드포인트입니다.

### 6.6. Admin (`/api/admin`)

관리자 대시보드, 주문 거래 감사, LLM 무의식 해몽 재연산 및 플랫폼 통합 유저 계정 모니터링을 위한 강력한 어드민 전용 백엔드 API 세트입니다.

> [!IMPORTANT]
> **공통 보안 요구사항 (Security Rules)**
> - **독립형 고정 관리자 인증 체계**: 관리자 페이지(`/admin/*`) 및 어드민 전용 API(`/api/admin/*`)는 일반 Supabase 소셜 로그인 세션과 완벽히 격리된 **독립형 전용 로그인 방식**을 가집니다.
>   - **관리자 계정**: ID `admin` / Password `admin1234!`
>   - **인증 메커니즘**: 성공적인 로그인 시 30일 동안 유효한 `admin_session=true` 보안 쿠키가 발급되며, 해당 쿠키의 존재 및 유효성 여부로 권한을 엄격하게 철저 검증합니다. 비인가 접근 시 `/admin-login`으로 즉시 안전하게 리다이렉트 처리되거나 API 단에서 `401 Unauthorized`를 반환합니다.
> - **보안 토큰 및 자격 증명 은닉**: 민감한 보안 키(`SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`)는 절대 클라이언트에 노출하지 않고 서버 사이드에서만 안전하게 사용합니다.
> - **비회원 연락 정보 마스킹**: 비회원 휴대폰 번호의 경우 개인정보 보호 정책에 따라 뒷자리 4자리를 마스킹 처리(`010-1234-****`)하여 응답합니다.
> 
> **예외 처리 및 견고성 확보 정책 (Graceful Fallback & System Resiliency)**
> - **우아한 예외 데이터 서빙 (Graceful Fallback)**: 플랫폼 초기 셋업 단계이거나 테스트 단계 등 실제 데이터베이스가 완전히 비어 있을 때 화면 멈춤이나 레이아웃 깨짐 현상을 방지하기 위해, 실 데이터가 전혀 없을 시 프리미엄 어드민 디자인 테마에 맞추어 완벽히 구조화된 가상 원장 데이터를 Fallback으로 안전하게 결합하여 제공합니다.
> - **비상 상태 보정 싱크 (Sync Integrity)**: 관리자 비상 강제 제어 툴(`PATCH`)을 사용하여 주문 거래 상태를 `SUCCESS`로 강제 승격/갱신할 시, 해당 주문에 매칭된 `dreams` 레코드의 AI 해몽 상태 또한 누락 없이 동기화(`PENDING` / `GENERATING`으로 자동 보정)하여 데이터의 도메인 무결성을 견고하게 유지합니다.


#### 6.6.1. `GET /api/admin/dashboard` (대시보드 통계 분석)
- **목적**: 기간별 매출 흐름, 가입 전환율, AI 시스템 안정성 등 주요 비즈니스 지표(KPI) 및 차트 데이터 실시간 조회
- **쿼리 파라미터**: `period` (기본값: `'7d'`, 허용값: `'today'`, `'7d'`, `'30d'`, `'year'`)
- **응답 스펙**:
  - `stats`: `totalRevenue`(실매출 합산), `totalOrders`(결제성공 건수), `totalUsers`(신규 유저), `aiSuccessRate`(해몽 성공율), 그리고 직전 동일 기간 대비 변동율(`revenueChange`, `ordersChange`, `usersChange`).
  - `chartData`: 시간별/일별/주별/분기별 매출을 실제 날짜 기반으로 배열 형태로 반환.
  - `productShares`: 텍스트 기본(1,500원) 및 이미지 추가(2,000원) 상품별 결제 건수, 매출액, 백분율 구성비.
  - `recentOrders`: 최근 결제 성공 주문 3~5건 (주문번호, 결제금액, 상태, 생성시간, 꿈 요약, 유저 유형).

#### 6.6.2. `GET /api/admin/orders` (전체 주문 거래 감사 장부)
- **목적**: 회원 및 비회원의 모든 결제 주문서 거래 내역 다중 조건 필터링 및 리스트 조회
- **쿼리 파라미터**:
  - `search` (주문번호, 이메일, 연락처, 꿈 키워드, 스타일 부분 검색)
  - `userType` (`'ALL'`, `'MEMBER'`, `'GUEST'`)
  - `status` (`'ALL'`, `'SUCCESS'`, `'PENDING'`, `'FAILED'`)
  - `productType` (`'ALL'`, `'1500'`, `'2000'`)
  - `sortBy` (`'date_desc'`, `'date_asc'`, `'amount_desc'`, `'amount_asc'`)
  - `page` (기본 `1`), `limit` (기본 `8`)
- **응답 스펙**: 필터링된 `OrderItem` 배열 및 페이지네이션 정보 (`totalCount`, `totalPages`, `currentPage`).

#### 6.6.3. `GET /api/admin/orders/[id]` (개별 주문 상세 감사)
- **목적**: 특정 거래 주문의 꿈 내용 원본, AI 텍스트 분석(상징물, 조언, 예측, 전문), 이미지 렌더링 경로 및 서버 트랜잭션 시스템 로그 상세 조회
- **응답 스펙**: 단일 주문 상세 데이터 및 RLS 우회 단계별 감사 로그(`systemLogs`) 배열.

#### 6.6.4. `PATCH /api/admin/orders/[id]` (관리자 비상 거래 보정)
- **목적**: PG사 비동기 통신 실패 또는 결제 승인 누락 등의 응급 상황 발생 시 관리자 권한으로 거래 상태를 강제 제어 및 보정
- **페이로드**: `{ "status": "SUCCESS" | "PENDING" | "FAILED" }`

#### 6.6.5. `POST /api/admin/orders/[id]/regenerate` (LLM 해몽/심상 재연산)
- **목적**: 모니터링 감사 중 품질 기준 미달 해몽 발견 시 LLM 해석 및 꿈 심상 이미지를 실시간 재생성
- **처리 흐름**: 요청 접수 시 주문 상태를 `GENERATING`으로 즉시 변경 후 `202 Accepted` 응답을 반환하고, Next.js `after()` API를 호출하여 백그라운드에서 Gemini LLM & Imagen 4.0 이미지 파이프라인(`processAIGeneration`)을 비동기로 실행.

#### 6.6.6. `GET /api/admin/users` (통합 유저 대장 감사)
- **목적**: 플랫폼에 유입된 회원 계정 및 비회원 게스트 전화번호에 대한 라이프타임 실적 통합 모니터링
- **쿼리 파라미터**:
  - `search` (이메일, 연락처, 닉네임, UUID 검색)
  - `userType` (`'ALL'`, `'MEMBER'`, `'GUEST'`)
  - `paymentStatus` (`'ALL'`, `'PAID'`, `'UNPAID'`)
  - `provider` (`'ALL'`, `'GOOGLE'`, `'KAKAO'`, `'EMAIL'`, `'GUEST_PHONE'`)
  - `sortBy` (`'date_desc'`, `'date_asc'`, `'spending_desc'`, `'orders_desc'`, `'name_asc'`)
  - `page` (기본 `1`), `limit` (기본 `8`)
- **응답 스펙**: 유저 프로필 리스트 및 드로어 노출용 개별 해몽 의뢰 히스토리(`dreamHistory`)를 서브 쿼리로 완전 동기화해 반환.


## 7. DB 스키마 설계 (DB Schema - Supabase)

Supabase PostgreSQL 환경에 맞춘 MECE한 테이블 설계입니다.

### 7.1. profiles (회원 정보)

Supabase의 기본 `auth.users` 테이블과 1:1로 연결되는 확장 프로필 테이블입니다. 관리자 권한 및 기본 유저 정보를 관리합니다.
| 컬럼명 | 데이터 타입 | 제약조건 (Null 여부 등) | 설명 |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | PK, FK(`auth.users.id`), **NOT NULL** | 유저 고유 ID |
| `email` | `text` | **NOT NULL** | 유저 이메일 |
| `nickname` | `text` | NULL | 유저 닉네임 |
| `provider` | `text` | NULL | 소셜 로그인 제공자 (google, kakao 등) |
| `role` | `text` | Default `'USER'`, **NOT NULL** | 권한 (`'USER'`, `'ADMIN'`) |
| `created_at` | `timestamptz` | Default `now()`, **NOT NULL** | 가입 일시 |

### 7.2. guests (비회원 정보)

비회원 주문 및 조회를 위한 정보를 저장합니다.
| 컬럼명 | 데이터 타입 | 제약조건 (Null 여부 등) | 설명 |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | PK, Default `uuid_generate_v4()`, **NOT NULL** | 비회원 고유 ID |
| `phone_number` | `text` | **NOT NULL** | 휴대폰 번호 (조회용 아이디 역할) |
| `password_hash` | `text` | **NOT NULL** | 암호화된 비밀번호 (조회용) |
| `created_at` | `timestamptz` | Default `now()`, **NOT NULL** | 최초 주문 일시 |

### 7.3. orders (주문 및 결제 내역)

회원과 비회원의 모든 결제 및 주문 정보를 관리합니다. 토스페이먼츠 연동 기준입니다.
| 컬럼명 | 데이터 타입 | 제약조건 (Null 여부 등) | 설명 |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | PK, Default `uuid_generate_v4()`, **NOT NULL** | 주문 고유 ID |
| `order_number` | `text` | Unique, **NOT NULL** | 토스페이먼츠 연동용 `orderId` |
| `user_type` | `text` | **NOT NULL** | 구매자 유형 (`'MEMBER'`, `'GUEST'`) |
| `profile_id` | `uuid` | FK(`profiles.id`), NULL | (회원인 경우) 구매자 ID |
| `guest_id` | `uuid` | FK(`guests.id`), NULL | (비회원인 경우) 비회원 ID |
| `total_amount` | `integer` | **NOT NULL** | 총 결제 금액 |
| `status` | `text` | Default `'PENDING'`, **NOT NULL** | 결제 상태 (`'PENDING'`, `'SUCCESS'`, `'FAILED'`) |
| `payment_key` | `text` | NULL | 토스페이먼츠 `paymentKey` |
| `created_at` | `timestamptz` | Default `now()`, **NOT NULL** | 주문 생성 일시 |
| `updated_at` | `timestamptz` | Default `now()`, **NOT NULL** | 주문 상태 업데이트 일시 |

### 7.4. dreams (해몽 및 결과 데이터)

주문과 1:1 (또는 1:N)로 연결되는 꿈 내용, AI 해몽 결과, 생성된 이미지를 저장합니다.
| 컬럼명 | 데이터 타입 | 제약조건 (Null 여부 등) | 설명 |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | PK, Default `uuid_generate_v4()`, **NOT NULL** | 해몽 고유 ID |
| `order_id` | `uuid` | FK(`orders.id`), **NOT NULL** | 결제된 주문 ID |
| `expert_style` | `text` | **NOT NULL** | 선택한 해몽 전문가 스타일 (프로이트, 융 등) |
| `dream_content` | `text` | **NOT NULL** | 유저가 입력한 꿈 내용 (Input) |
| `ai_analysis` | `text` | NULL | LLM이 생성한 심층 해몽 텍스트 (Output) |
| `image_url` | `text` | NULL | 생성된 꿈 이미지 URL (옵션 결제 시) |
| `is_public` | `boolean` | Default `false`, **NOT NULL** | 공개 피드 노출 여부 |
| `status` | `text` | Default `'PENDING'`, **NOT NULL** | AI 처리 상태 (`'PENDING'`, `'GENERATING'`, `'COMPLETED'`, `'FAILED'`) |
| `created_at` | `timestamptz` | Default `now()`, **NOT NULL** | 레코드 생성 일시 |
| `updated_at` | `timestamptz` | Default `now()`, **NOT NULL** | 해몽 완료/업데이트 일시 |
